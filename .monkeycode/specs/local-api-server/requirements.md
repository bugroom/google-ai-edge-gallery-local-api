# 本地API服务功能需求规格

## 1. 引言

### 1.1 背景
Google AI Edge Gallery 应用已支持模型下载和本地推理，但仅限于应用内使用。为了提升模型利用价值，需要将应用转换为本地AI推理服务器，允许其他设备/应用调用已下载的模型进行推理。

### 1.2 目标
- 在Gallery应用内启动本地HTTP服务器
- 提供标准化的REST API接口
- 兼容OpenAI API格式，便于集成
- 保证安全性和性能

### 1.3 范围
- 本地HTTP服务器
- REST API接口实现
- 基础认证机制
- 设置界面和控制面板
- API文档界面

---

## 2. 功能需求

### 2.1 核心功能 (P0)

#### FR-001: 本地HTTP服务器
**描述**: 在Gallery应用内启动本地HTTP服务器

**验收标准**:
- 服务器可启动/停止
- 默认监听 127.0.0.1:8080
- 支持自定义端口
- 支持配置监听地址（本地/局域网）
- 服务器状态实时显示

**优先级**: P0

---

#### FR-002: 模型列表API
**描述**: 提供获取已下载模型列表的API

**验收标准**:
- 端点: `GET /v1/models`
- 返回所有已下载模型
- 响应格式兼容OpenAI API
- 包含模型ID、名称、大小等信息

**优先级**: P0

---

#### FR-003: 聊天补全API
**描述**: 提供多轮对话的聊天补全API

**验收标准**:
- 端点: `POST /v1/chat/completions`
- 支持多轮对话上下文
- 支持参数配置（temperature, max_tokens等）
- 返回格式兼容OpenAI API
- 包含使用统计（token计数）

**优先级**: P0

---

#### FR-004: 健康检查API
**描述**: 提供服务健康状态检查的API

**验收标准**:
- 端点: `GET /health`
- 返回服务器运行状态
- 返回当前连接数
- 返回加载的模型信息

**优先级**: P0

---

#### FR-005: 模型切换功能
**描述**: 支持动态切换推理模型

**验收标准**:
- API支持指定模型ID
- 自动加载目标模型
- 卸载未使用模型以释放内存
- 处理模型不存在的错误

**优先级**: P0

---

### 2.2 增强功能 (P1)

#### FR-006: 流式响应
**描述**: 支持SSE（Server-Sent Events）流式输出

**验收标准**:
- 支持 `stream=true` 参数
- 实时输出生成内容
- 兼容OpenAI流式格式
- 支持取消流式请求

**优先级**: P1

---

#### FR-007: API Key认证
**描述**: 提供API Key认证机制

**验收标准**:
- 支持 `Authorization: Bearer` 头
- 支持自定义Token
- 可生成随机Token
- 支持禁用认证（仅本地）

**优先级**: P1

---

#### FR-008: 设置界面
**描述**: 提供配置和管理API服务的界面

**验收标准**:
- 服务开关控制
- 端口配置
- 认证方式选择
- Token管理
- 访问控制配置
- 服务状态显示

**优先级**: P1

---

#### FR-009: 错误处理
**描述**: 提供完善的错误处理和日志记录

**验收标准**:
- 详细的错误信息
- HTTP状态码规范
- 请求日志记录
- 错误日志记录

**优先级**: P1

---

## 3. 非功能需求

### 3.1 性能需求

#### NFR-001: 响应时间
- API响应延迟 < 100ms（不含推理时间）
- 首字节时间 < 500ms

#### NFR-002: 并发处理
- 支持2-5个并发请求
- 请求队列容量 ≥ 10

#### NFR-003: 资源管理
- 内存增长可控
- 及时释放推理资源
- 自动卸载未使用模型

---

### 3.2 安全需求

#### NFR-004: 网络隔离
- 默认仅监听本地回环地址 (127.0.0.1)
- 可选配置允许的局域网IP段

#### NFR-005: 认证授权
- 支持API Key认证
- 支持禁用认证（仅本地使用）
- Token可配置和更新

#### NFR-006: 访问控制
- 请求频率限制
- 并发连接数限制
- 超时保护

---

### 3.3 可用性需求

#### NFR-007: 稳定性
- 服务器可长时间运行
- 异常情况下自动恢复
- 不会因单个请求崩溃

#### NFR-008: 可配置性
- 所有关键参数可配置
- 配置实时生效
- 配置持久化存储

#### NFR-009: 可维护性
- 清晰的日志记录
- 详细的错误信息
- 便于调试和排查问题

---

## 4. 约束条件

### 4.1 技术约束
- 必须使用Kotlin开发
- 必须兼容Android 9.0 (API 28)及以上
- 必须复用现有的LiteRT-LM推理引擎
- API格式兼容OpenAI标准

### 4.2 资源约束
- HTTP服务器必须轻量级
- 不能显著影响应用性能
- 内存占用增加 < 100MB

### 4.3 兼容性约束
- API响应格式兼容OpenAI API
- 支持标准HTTP客户端调用
- 支持常见编程语言（Python, JavaScript, cURL等）

## 5. 用例场景

### UC-001: 本地开发测试
**描述**: 开发者在PC上调用手机模型的推理服务进行测试

**主要步骤**:
1. 在Gallery应用中启动本地API服务
2. 在PC上使用cURL或Postman调用API
3. 获取推理结果进行验证

**前置条件**: 已下载至少一个模型

**后置条件**: API服务正常运行

---

### UC-002: 跨设备协作
**描述**: 手机作为推理服务器，平板/PC作为客户端

**主要步骤**:
1. 在手机上启动API服务并允许局域网访问
2. 在平板/PC上配置API Token
3. 平板/PC调用手机上的模型进行推理

**前置条件**: 设备在同一局域网

**后置条件**: 推理服务可跨设备访问

---

### UC-003: 隐私保护场景
**描述**: 数据不出本地设备，完全离线运行

**主要步骤**:
1. 下载模型到本地
2. 启动本地API服务（仅本地访问）
3. 客户端调用API，数据完全本地处理

**前置条件**: 已下载模型

**后置条件**: 数据不离开本地设备

## 8. 术语定义

- **API服务器**: 提供REST API接口的HTTP服务器
- **LiteRT-LM**: Google的轻量级推理引擎
- **OpenAI API格式**: OpenAI公司定义的API标准格式
- **SSE**: Server-Sent Events，服务器推送事件技术
- **Token**: 在LLM中指文本单元，在认证中指访问令牌
